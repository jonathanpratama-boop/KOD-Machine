## summary
Map of what idx-signals (HEAD = claude/idx-signals-test-repo-ds0jw7, commit e635e22) can express, with PR #7 (origin/claude/e4-fade-short-side) and PR #3 (origin/claude/us-pipeline-v1) read via git show.

SIGNAL INTERFACE: a rule is a frozen module exposing compute(view) -> float array shaped (names x sessions) with values 1 (signal at that close), 0 (evaluated, none), NaN (not evaluable). The view (rules.RuleView) carries exactly 12 exchange fields: close, prev, high, low, volume, value, present, tradeable, lock_up, lock_down, listed_shares, open, plus tickers and dates; nothing from the corporate-action registry or unit factors. Causality is by construction: backtest calls compute once per session d on a view holding sessions 0..d and only names listed by d, records column d, then checks a full-window call agrees (LookaheadError otherwise). A static AST audit forbids any import beyond numpy/pandas/math/zlib/hashlib/itertools/statistics/idxsig.market, any I/O, module-level non-literals, classes, decorators, state; a PEP 578 sandbox blocks file/network/process/frame/heap access during compute. A rule CAN use the full cross-section at d (E1 uses the cross-sectional median return; E4 conditions on BTC's 50-session mean because BTC is a row of the crypto panel) but CANNOT emit scores, weights, sizes, stops or multi-leg instructions.

EXECUTION (HEAD): one independent trade per (name, signal session), fixed notional (IDX Rp10m, US/CRYPTO $5k), whole lots (IDX 100, else 1), entry at the close of s+entry_lag (IDX) or the open of s+1 (US/CRYPTO), exit at the close of entry+holding_days rolled forward while untraded or locked at ARB; IDX ARA lock refuses entry. Fill models: A (ex-post 10% of entry-session volume), B (FILL-B-v1, decision-time median volume, open entries, as_traded units), C (FILL-C-v1, decision-time, IDX close entries, registry-scaled). Costs: per-side fees (IDX 0.15%/0.25%; US 0/SEC fee + price-tier cost 1.5%..0.05%; CRYPTO 0.1%+0.1%), no price impact, no dividends, no carry on longs. Corporate actions: registry (IDX) scales only verified splits/stock dividends; rights issues and unresolved resets exclude the trade; US/CRYPTO use ca_mode adjusted. Plans (research/E3): entry fixed/confirm/pullback/unlock within an entry window; exit fixed/stop_ref/first_down; HEAD restricts conditional plans to close entries (IDX). Long only on HEAD.

E4 BRANCH ADDS: side short (open-entry markets only, refused under auto-rejection limits), exits stop_high/first_up, open-based conditional entries for US/CRYPTO longs and shorts, carry_per_session from the profile (US 0.3%/session borrow, CRYPTO 0.05%/day funding), optional isolated-margin liquidation on the session high, jump_ratio exclusion (EXCLUDED_DATA_JUMP), GLOBAL_HOLDOUT (2024-01-01 on) guard for US/CRYPTO, --side and e4-* CLI, tail statistics and hit-rate/tail admissibility. Recorded results: v1 0/144 admissible; v2 31/288 admissible, frozen pair failed validation on 2023 (34 scored, avg -1.50%, p 0.78, 3 liquidations).

MATCHED CONTROLS (controls v2): for each attempted signal, 200 draws on the same session from evaluable names in the same price_band, liquidity quintile (20-session median traded value), market_cap quintile (close x listed_shares; IDX mirror era only), volatility tercile, momentum tercile, drawdown tercile, listing_age bucket; relaxed from the last feature until >=5 names match; executed under the identical plan; plus a same-session uniform baseline. Not matched: sector, board, free float (no point-in-time data).

RECORDING: write_run refuses a dirty idxsig/ tree, creates results/runs/<UTC stamp>_<rule_id>_<version>/ with summary.json, trades.csv.gz, random_draws.csv, REPORT.md (exclusive-create, read-only), appends one line to results/RUNS.jsonl with file hashes, and git-commits; verify-runs and tools/check_append_only.py (pre-commit) enforce append-only. Experiment modules (e3.py, e4.py) read research/<E>/protocol.json (sha256 stamped), require a precondition reproduce stage, run a discovery grid (plan_grid x detector candidates) through backtest.run with a signal cache, write plans.csv/summary.json, apply a pre-registered admissibility+selection rule, require SELECTED to be committed into the rule module (so the rule hash covers the plan), then one validation run recorded via write_run.

PR #3 (us-pipeline-v1) is NOT in HEAD, branched before E3 (merge-base c09a27a), and its diff removes E3 plan code; it adds exec_us.py (EXEC-US-v1 per-trade stop/limit/risk sizing), contract.py (EXEC-US-v2.1 single cash Account with reservations, ADV priority, replay + forward_step) and fill model B2. The local claude/us-breakout-v1 branch extends it with breakout.py and research/US_BREAKOUT_v1 (standalone runner, result: no edge on 2023).

CANNOT be expressed today: intraday anything; a capital-constrained multi-name portfolio with the matched-control method; pairs/spreads/multi-leg; external or non-price inputs (fundamentals, news, borrow/funding history, sector, index membership); signal strength/ranking/sizing; trailing stops, profit targets, limit entries (HEAD); shorts on IDX; dividends; leverage/derivatives beyond E4's 1x liquidation proxy.
